# Аптечка — адаптивный MVP-прототип

Статический демо-сайт на чистых HTML/CSS/JavaScript. Один и тот же URL работает на телефоне и ноутбуке:

- **Телефон до 820 px:** полноэкранный интерфейс и нижняя навигация.
- **Ноутбук / ПК от 821 px:** рабочая область с боковым списком экранов, расширенным контентом и при достаточной ширине — панелью подсказок.
- **PWA:** сайт можно добавить на домашний экран телефона; статические файлы кэшируются для офлайн-демонстрации.

## Быстрая публикация через интерфейс GitHub

1. Авторизуйтесь на https://github.com и нажмите **New repository**.
2. Назовите репозиторий `aptechka-mvp` и выберите **Public** (для бесплатного GitHub Pages).
3. Откройте созданный репозиторий, выберите **Add file → Upload files**.
4. **Распакуйте ZIP и загрузите содержимое папки `aptechka-github-pages`, а не сам ZIP.** На верхнем уровне должен лежать `index.html`. Сохраните структуру каталогов, особенно папку `assets`.
5. Нажмите **Commit changes**.
6. Откройте **Settings → Pages → Build and deployment → Source: Deploy from a branch**.
7. Выберите **Branch: main**, папку **/(root)**, нажмите **Save**.
8. Адрес после публикации: `https://<ваш-логин>.github.io/aptechka-mvp/` (замените `<ваш-логин>`).

### Если удобнее через git

```bash
git init
git branch -M main
git add .
git commit -m "Initial responsive Aptechka MVP"
git remote add origin https://github.com/USERNAME/aptechka-mvp.git
git push -u origin main
```

Сначала создайте пустой репозиторий GitHub и замените USERNAME. Затем включите Pages согласно пунктам 6–7.

## Локальный запуск

Можно просто открыть `index.html` в браузере (без офлайнового PWA-кеша). Или запустить локальный сервер:

```bash
python3 -m http.server 8000
```

Затем открыть http://localhost:8000 . Через Chrome DevTools → Device Toolbar можно проверить мобильный вид.

## Что уже работает

- 8 экранов и переходы между ними;
- изменение количества упаковок в демонстрационных данных;
- автоматический пересчёт дефицита препаратов;
- отметка приобретения препарата;
- отметки о запланированных действиях;
- включение/выключение демонстрационного доступа родственника.

## ВАЖНО: чего здесь нет

- реального распознавания назначений (OCR), медицинской интерпретации, push-уведомлений;
- регистрации пользователей, серверной синхронизации между устройствами;
- настоящих медицинских данных или отправки файлов на сервер;
- готовности к работе с реальными медицинскими документами.

**GitHub Pages — публичный статический хостинг. Не добавляйте реальные назначения, персональные или медицинские данные в репозиторий или код страницы.** Для работающего медицинского продукта понадобятся backend, аутентификация, разграничение доступа и правовая оценка.

## Структура

```
aptechka-github-pages/
├── index.html               # 8 экранов, JS и адаптивный CSS
├── manifest.webmanifest     # установка на главный экран
├── service-worker.js        # кеширование демо для офлайн-просмотра
├── .nojekyll                # публикация файлов без Jekyll
└── assets/
    ├── icon-192.png
    └── icon-512.png
```

Изменения публикуются автоматически после новых коммитов в `main`.
